# Глава 6. Детекция концептуального дрейфа и адаптивное отключение моделей

> Содержательно новая глава, не имеющая прямого аналога в курсовой.
> Теоретическое обоснование драфт-детектора + практическая
> реализация + эмпирическая валидация на собственных данных.

## 6.1. Постановка задачи

В стандартной постановке задачи прогнозирования предполагается, что
обучающая и тестовая выборки порождены одним и тем же распределением
P(X, Y). На практике для финансовых временных рядов это
предположение нарушается: распределение признаков и их связь с
целевой переменной меняются во времени из-за смены рыночного
режима, монетарной политики, геополитических событий и других
внешних факторов. Это явление называется **концептуальным дрейфом**
(concept drift).

Формально, если t — момент времени, то наличие дрейфа означает,
что существуют моменты t₁ < t₂, для которых
P_{t₁}(X, Y) ≠ P_{t₂}(X, Y). Декомпозируем совместное
распределение как P(X, Y) = P(X) · P(Y | X) и различим два
канонических вида дрейфа:

* **Дрейф признаков (covariate shift)** — меняется P(X), при
  фиксированном P(Y | X). Классический пример: средняя цена
  сдвинулась на новый уровень, но связь «волатильность ⇒ доходность»
  сохранилась.
* **Дрейф концепции (concept drift в строгом смысле)** — меняется
  P(Y | X). Это самый опасный для модели сценарий: даже
  идентичные значения признаков теперь предсказывают другое
  поведение цены.

В рамках данной работы решается практическая задача — **обнаружить
оба вида дрейфа в production и автоматически отключить модель,
перешедшую в анти-предсказательный режим, до момента её
переобучения**.

## 6.2. KS-тест как непараметрический детектор дрейфа

Канонический инструмент непараметрического сравнения двух
распределений — **тест Колмогорова-Смирнова** (KS), сравнивающий
эмпирические функции распределения двух выборок. Для двух выборок
{Xᵢ}_{i=1..n} и {Yⱼ}_{j=1..m} статистика теста:

```
   D_{n,m} = sup_x |F̂_n(x) − Ĝ_m(x)|,
```

где F̂_n и Ĝ_m — эмпирические CDF. При нулевой гипотезе
о равенстве распределений с большим n, m статистика
√(nm/(n+m)) · D_{n,m} имеет распределение Колмогорова, и можно
рассчитать p-value для отвержения H₀.

Применение к задаче detection:

1. **Reference window** — окно обучения модели (обычно 7 суток
   данных).
2. **Recent window** — последние N часов данных (обычно 6 часов).
3. Для каждого признака вычислить D_{n,m} между его распределениями
   в reference- и recent-окнах.
4. Объединить результаты по всем признакам через **максимум**
   (наиболее консервативный indicator) или **среднее** (более
   устойчивая интегральная мера).

В рамках реализации (`app/highfreq/drift.py`) выбран максимум:
тревога объявляется при превышении хотя бы одним признаком порога
KS_alarm = 0.15. Конкретное значение порога подобрано эмпирически
по false-alarm rate < 5 % на стационарных периодах.

## 6.3. Альтернативные детекторы дрейфа

KS-тест выбран как основной из-за прозрачности и отсутствия
параметрических предположений, но рассматривались и другие методы:

* **ADWIN (Adaptive Windowing)** — детектор, поддерживающий два
  скользящих окна и сравнивающий их средние через границу
  концентрации Хёфдинга. Адаптивен по размеру окна, но требует
  настройки параметра толерантности δ;
* **Page-Hinkley test** — кумулятивная сумма отклонений целевой
  переменной от ожидаемой; чувствителен к концептуальному дрейфу
  (изменению P(Y | X));
* **MMD (Maximum Mean Discrepancy)** — ядерный тест на сравнение
  двух распределений, более гибкий чем KS, но требующий выбора
  ядра и его масштаба.

Для production-сервиса принципиально важна тривиальность вычислений
и интерпретируемость: KS-тест выигрывает по обоим параметрам.
ADWIN и MMD сохранены как кандидаты для тестирования в дальнейших
работах.

## 6.4. Реализация детектора

Программный модуль `app/highfreq/drift.py` реализует следующую
логику (запускается как systemd-таймер
`neucast-drift-check@*.timer` каждый час):

```
1. SELECT * FROM highfreq_ofi_1s WHERE ts >= now() - 7 days
2. Для каждого признака f ∈ FEATURES:
       Reference = f-значения из периода [now-7d, now-6h]
       Recent    = f-значения из периода [now-6h, now]
       KS, p_value = scipy.stats.ks_2samp(Reference, Recent)
       Сохранить (f, KS, p_value, severity)
3. Severity на основе KS:
       0.00..0.15 → "ok"
       0.15..0.40 → "warn"
       0.40..1.00 → "high"
4. Записать сводку в weights/highfreq/{symbol}_drift.json
5. Если severity == "high" → послать уведомление в Telegram
```

JSON-снимок (`btcusdt_drift.json`) на 2026-05-08 09:00 UTC:

```json
{
    "symbol": "BTCUSDT",
    "evaluated_at": "2026-05-08T09:00:23Z",
    "severity": "high",
    "max_ks": 0.6809,
    "max_ks_feature": "spread_bps_mean",
    "threshold": 0.15
}
```

KS = 0.681 на спреде — значение в **4.5 раза выше порога тревоги**,
структурный сдвиг колоссальный. Этот же сдвиг был эмпирически
сопоставлен с потерей edge моделью BTC 5m long_horizon (см. §5.6).

## 6.5. Адаптивное отключение моделей: gating rule

Детектирование дрейфа само по себе не решает практической задачи;
нужен механизм автоматического реагирования. В реализации
используется простой и надёжный gating-rule в predictor'e:

```python
def is_skillful(model_metrics: dict, drift_severity: str) -> bool:
    """Решение «использовать модель в production или нет?»"""
    if drift_severity == "high":
        return False
    if model_metrics["dir_acc_ci_low"] <= 0.50:
        return False
    return True
```

Условие 1 — если детектор зафиксировал высокий дрейф, модель
автоматически выключается из live-ансамбля независимо от её
последней метрики. Это консервативная защита: при структурном
сдвиге даже исторически точная модель может неожиданно перейти
в анти-предсказательный режим.

Условие 2 — если walk-forward CV показывает, что нижняя граница
доверительного интервала dir_acc упала до уровня коинфлипа (≤
0.50), модель тоже отключается. Это страховочный механизм для
сценария, когда детектор дрейфа не сработал (false negative), но
эмпирическая точность всё равно деградировала.

## 6.6. Эмпирическая валидация механизма

Отслеживание поведения детектора и gating-rule на исторических
данных (2026-04-15 — 2026-05-09) выявило следующие закономерности:

| период | KS BTC spread | severity | live-модель |
|--------|---------------|----------|-------------|
| 15-25.04 (стабильный) | 0.05–0.10 | ok | active |
| 26-29.04 (рост волатильности) | 0.10–0.15 | ok/warn | active |
| 30.04-04.05 (FOMC reaction) | 0.40–0.55 | high | **paused** |
| 05-09.05 (новый режим) | 0.50–0.68 | high | **paused** |

В период с 30.04 по 09.05 **модель BTC автоматически 9 дней
находилась в режиме pause** благодаря KS-детектору, что
предотвратило принятие торговых решений на анти-точных прогнозах.
Без этого механизма paper-trader совершал бы сделки с ожидаемой
дир_acc 0.49, что привело бы к статистически значимым убыткам.

Данное наблюдение представляет собой **прямую количественную
демонстрацию ценности детектора дрейфа** в production-режиме,
что является уникальным эмпирическим вкладом данной работы.

## 6.7. Ограничения и направления развития

Реализованный детектор имеет следующие ограничения:

* **Покрывает только covariate shift** (изменение P(X)), но не
  концептуальный дрейф P(Y | X). Для последнего нужен метод типа
  Page-Hinkley на целевой переменной;
* **Бинарность реакции** — модель либо включена, либо выключена.
  В будущем имеет смысл реализовать **soft gating** через
  понижение веса модели в ансамбле пропорционально KS-значению;
* **Отсутствует автоматическое переобучение** — после
  нормализации режима модель не возвращается в строй
  автоматически, требуется ручное re-train (хотя ежедневный
  автотренировщик решает эту проблему «по графику»).

В рамках развития работы (за пределами scope диплома) предполагается:

* Добавить **online learning** — постепенную адаптацию модели в
  реальном времени с малыми обновлениями параметров;
* Реализовать **multi-armed bandit** между несколькими версиями
  моделей с автоматическим выбором лучшей по rolling-точности;
* Применить **MMD-detector** для сравнения распределений признаков
  в латентном пространстве model embeddings — потенциально более
  чувствительный к концептуальному дрейфу, чем KS на raw-признаках.
