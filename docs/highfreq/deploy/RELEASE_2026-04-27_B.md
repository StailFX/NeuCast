# Release 2026-04-27 B — Backup expansion

3 archival/backup additions, 22 new tests (414 total green). Closes
the data-loss gap that release A's cron-stale alerts surfaced: prior
to this, `paper_trades` and `highfreq_ofi_1s` were not backed up
*at all* — a Tokyo VPS death meant losing every paper trade and every
microstructure observation ever collected.

## What's new

| Change | Effect on RPO (Tokyo death) | Files |
|---|---|---|
| **L2 archive: retention 7 → 2 days, timer 24h → every 4h** | L2 data loss capped at ~2 days (was 7d); failed archive runs retried within 4h | timer + service updated |
| **paper_trades backup** (daily 02:30 UTC, no delete from Postgres) | paper_trades loss capped at ~24h (was ∞) | `tools/archive_paper_trades_to_s3.py`, systemd unit |
| **OFI 1-sec archive** (daily 02:45 UTC, retention 7 days, atomic) | OFI loss capped at ~7 days (was ∞) | `tools/archive_ofi_1s_to_s3.py`, systemd unit |
| **2 new cron-stale alerts** | OFI / paper-trades-backup heartbeat staleness pages within 25h | alerts.yaml |
| **DR drill doc updated** | Manual drill commands for new archive types documented | dr_drill.md |

**RPO before this release:**

```
L2 snapshots:    up to 7 days lost on Tokyo death
paper_trades:    EVERYTHING lost (no backup)
ofi 1s:          EVERYTHING lost (no backup)
```

**RPO after this release:**

```
L2 snapshots:    up to 2 days lost
paper_trades:    up to 24h lost
ofi 1s:          up to 7 days lost (matches trainer's 3-day window with buffer)
```

> ⚠️ **Honest caveat on the L2 timer.** The 4-hour timer cadence does
> NOT give a 4-hour RPO — the script archives WHOLE complete days, so
> the bound on lost data is set by `--retention-days` (now 2). The
> 4h timer just gives faster retry resilience; a transient S3/Postgres
> hiccup at 02:00 UTC retries at 06:00 UTC instead of waiting 24h.
> True 4h RPO requires hour-bucket chunking — a separate redesign,
> tracked as a future release if needed.

## Tokyo deployment steps

The diff is fully additive (no live-trading semantics change).
Deploy in this order, all as the existing service user:

### 1. Pull new code

```bash
cd /opt/neucast
sudo -u stailfx git fetch origin main
sudo -u stailfx git pull --ff-only origin main
sudo -u stailfx /opt/neucast/venv/bin/pip install -r docs/highfreq/deploy/requirements-highfreq.txt
```

(No new top-level deps — boto3 + pyarrow + psycopg2-binary already installed.)

### 2. Install new systemd units

```bash
sudo cp docs/highfreq/deploy/neucast-paper-trades-backup.service /etc/systemd/system/
sudo cp docs/highfreq/deploy/neucast-paper-trades-backup.timer   /etc/systemd/system/
sudo cp docs/highfreq/deploy/neucast-ofi-archive.service         /etc/systemd/system/
sudo cp docs/highfreq/deploy/neucast-ofi-archive.timer           /etc/systemd/system/
# L2 timer + service files were modified — overwrite the existing ones:
sudo cp docs/highfreq/deploy/neucast-l2-archive.service /etc/systemd/system/
sudo cp docs/highfreq/deploy/neucast-l2-archive.timer   /etc/systemd/system/

sudo systemctl daemon-reload
sudo systemctl enable --now neucast-paper-trades-backup.timer
sudo systemctl enable --now neucast-ofi-archive.timer
# Restart L2 timer to pick up the new schedule.
sudo systemctl restart neucast-l2-archive.timer

# Verify all 4 are armed.
sudo systemctl list-timers 'neucast-l2-archive.timer' \
                          'neucast-paper-trades-backup.timer' \
                          'neucast-ofi-archive.timer' \
                          'neucast-prom-backup.timer'
```

### 3. Reload Grafana alert rules

```bash
sudo cp docs/highfreq/deploy/grafana/alerting/alerts.yaml \
        /etc/grafana/provisioning/alerting/alerts.yaml
sudo systemctl restart grafana-server

# Confirm the 2 new alerts are registered.
curl -s -u admin:<pass> http://127.0.0.1:3000/api/v1/provisioning/alert-rules \
  | jq '.[] | select(.uid | test("(ofi-archive|paper-trades-backup)-stale-rule")) | .title'
```

Expected:
```
"OFI 1-sec archive cron hasn't succeeded in >25h"
"paper_trades backup cron hasn't succeeded in >25h"
```

### 4. **Ship current data to S3 immediately** (don't wait for the timers)

```bash
cd /opt/neucast

# 1. paper_trades backup — fastest (smallest data).
sudo systemctl start neucast-paper-trades-backup.service
journalctl -u neucast-paper-trades-backup.service --since "2 min ago"

# 2. OFI 1-sec archive — bulk of the data, may take 30-60s for catch-up.
sudo systemctl start neucast-ofi-archive.service
journalctl -u neucast-ofi-archive.service --since "2 min ago"

# 3. L2 archive (with new retention=2 — re-archives any days now eligible).
sudo systemctl start neucast-l2-archive.service
journalctl -u neucast-l2-archive.service --since "2 min ago"
```

**Expected output per run:**
* `DONE: uploaded=N days (M rows, K KB) | ...`
* No `failed=N` lines (or `failed=0`).
* In `/var/lib/node_exporter/textfile_collector/`:
  * `neucast_hf_l2_archive.prom`
  * `neucast_hf_paper_trades_backup.prom`
  * `neucast_hf_ofi_archive.prom`

### 5. Verify in S3

```bash
# Pull credentials from the same env file the cron uses.
set -a; source /etc/neucast/env; set +a

aws --endpoint-url "$YANDEX_S3_ENDPOINT" s3 ls "s3://$YANDEX_S3_BUCKET/highfreq_l2/" --recursive | tail -10
aws --endpoint-url "$YANDEX_S3_ENDPOINT" s3 ls "s3://$YANDEX_S3_BUCKET/highfreq_ofi_1s/" --recursive | tail -10
aws --endpoint-url "$YANDEX_S3_ENDPOINT" s3 ls "s3://$YANDEX_S3_BUCKET/paper_trades_backup/" --recursive | tail -10
```

Expected: per-(symbol, day) Parquet files for the last ~30 days.

### 6. Verify hot Postgres shrunk

```bash
docker exec neucast-postgres psql -U neucast -d neucast -c "
  SELECT 'highfreq_l2_snapshots' AS tbl, COUNT(*) FROM highfreq_l2_snapshots
  UNION ALL
  SELECT 'highfreq_ofi_1s', COUNT(*) FROM highfreq_ofi_1s
  UNION ALL
  SELECT 'paper_trades', COUNT(*) FROM paper_trades
  ORDER BY tbl;
"
```

Expected: hot row counts decreased for L2 and OFI; paper_trades unchanged.

### 7. Run a fresh DR drill against the new archives

```bash
sudo -u stailfx bash -lc '
  set -a; source /etc/neucast/env; set +a
  python -m tools.dr_drill_l2 --day "$(date -u -d "3 days ago" +%F)"
' | tee "docs/highfreq/dr_drill_runs/$(date -u +%F)-post-release-B.json" \
  | jq '.overall_ok, (.results[] | {symbol, rows_in_parquet, schema_ok})'
```

Expected: `overall_ok: true` for every symbol-day.

## Rollback

* **L2 timer/service**: revert to previous (daily, retention=7) by
  `git revert` of those two files only — purely config, no code path
  changes.
* **paper_trades backup**: `sudo systemctl disable --now neucast-paper-trades-backup.timer`.
  Already-uploaded S3 objects can stay (no delete = no harm). Drop
  the alert rule from `alerts.yaml`.
* **OFI archive**: `sudo systemctl disable --now neucast-ofi-archive.timer`.
  Hot Postgres will accumulate again (disk-full alert at 85% will
  give plenty of warning). Drop the alert rule from `alerts.yaml`.
